# OfficeBay pillars

| Pillar | Healthy when | Current state |
|---|---|---|
| P1 - Suite and note-document usability | Existing editors retain fidelity; organized note documents meet their parity checks | Existing suite inherited; notebook unimplemented; Windows baseline pending |
| P2 - Agent composition | Notebook uses inherited runtime/providers, validated tools and inspectable outcomes | Reuse seams inspected; notebook skill unimplemented |
| P3 - Identity and durable state | Document/note IDs, marks, references and revisions survive save/move/reopen | Contracts drafted; manager/core/history unimplemented |
| P4 - Grounding | Referenced sources and extraction limits remain inspectable | Existing format parsers available; notebook grounding unimplemented |
| P5 - Work-anchored creation | Selected notes/marks produce verified editable outputs with source links | Required; no notebook workflow implemented |
| P6 - Extensibility and cross-host reuse | New contributions avoid repeated legacy edits; one core works across three hosts | Hardcoded shell seams mapped; extension bridge and shared core unimplemented |
| P7 - Independent identity and providers | OfficeBay branding and no original hosted dependency, without lost capabilities | Removal and branding unimplemented |

Documentation and verification apply to every pillar. Claims of parity require real host evidence, including failure behavior. The project is in planning; inherited suite capabilities must not be confused with implemented OfficeBay additions.
